# TrustVault

TrustVault is a learning/demo application for private document storage, explicit sharing permissions, and a hash-linked audit trail. It uses FastAPI, SQLAlchemy, PostgreSQL, Alembic, and a plain HTML/CSS/JavaScript frontend.

## Features

- Account registration and login; passwords are hashed with Argon2 via `pwdlib`.
- JWT bearer authentication (30-minute expiry).
- Upload `.pdf`, `.txt`, `.png`, `.jpg`, `.jpeg` files up to 5 MB; storage uses random server-side names.
- Owners can grant/revoke `READ` or `EDIT` permission.
- Owners and explicitly shared users can list/download documents; `EDIT` can update display name/category.
- Owners can delete documents. Historical audit records are retained with the document reference cleared.
- Search by filename and category; optional owner ID filter is applied only to documents already visible to the signed-in user.
- Admin-only audit listing and hash-chain verification.
- `/docs` provides the OpenAPI/Swagger API explorer.

## Local setup (Windows PowerShell)

1. Install Python 3.12+ and PostgreSQL 15+ (Python 3.12 is recommended for deployment compatibility).
2. Create and activate a virtual environment:

   ```powershell
   py -3.12 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```

3. Copy `.env.example` to `.env`; update `DATABASE_URL` with your PostgreSQL credentials and set a long random `JWT_SECRET_KEY`. If the password has reserved URL characters, URL-encode them in the connection URL.
4. Create an empty PostgreSQL database and user matching `DATABASE_URL`.
5. Apply migrations and run the app:

   ```powershell
   python -m alembic upgrade head
   python -m uvicorn app.main:app --reload
   ```

6. Visit `http://127.0.0.1:8000/` for the frontend, `http://127.0.0.1:8000/docs` for API docs, and `http://127.0.0.1:8000/health` for health status.

### Create an administrator

Public registration always creates a `viewer`; it cannot create admins. From a trusted local shell after setting `.env`, set temporary environment variables and run the helper. Example PowerShell:

```powershell
$env:ADMIN_USERNAME = "vaultadmin"
$env:ADMIN_EMAIL = "admin@example.com"
$env:ADMIN_PASSWORD = "use-a-unique-password-at-least-12-chars"
python create_admin.py
Remove-Item Env:ADMIN_USERNAME, Env:ADMIN_EMAIL, Env:ADMIN_PASSWORD
```

Use a real unique password; do not use the example value. The helper creates/promotes only the exact account supplied.

## Tests

```powershell
python -m pytest -q
```

Tests use an in-memory SQLite database via a FastAPI dependency override, so they do not change your PostgreSQL data.

## Deployment (Render + PostgreSQL provider)

A starter `render.yaml` is included. Create a managed PostgreSQL database with a provider you choose, create a Render web service from this repository, and set `DATABASE_URL` to the provider's **internal** connection URL when supported. `JWT_SECRET_KEY` is generated by Render's blueprint. The service runs Alembic migrations before starting Uvicorn. Confirm the provider's current pricing, sleep behavior, storage persistence, and database limits before relying on any free tier; these policies can change.

**Important:** local `storage/` is not durable across many free web-service deployments/restarts. For real use, move files to a private object store with access controls, encryption, lifecycle/backup policy, and signed short-lived downloads. Do not deploy sensitive real documents to this demo configuration. Never put secrets in GitHub.

## API overview

- `POST /auth/register` — create viewer account.
- `POST /auth/login` — form-encoded username/password, returns bearer token.
- `GET /auth/me` — current account.
- `POST /documents/upload` — multipart file + category query parameter.
- `GET /documents?search=&category=&owner_id=` — owned/shared visible files.
- `GET /documents/{id}/download` — owner or READ/EDIT access.
- `PATCH /documents/{id}/metadata` — owner or EDIT access.
- `POST /documents/{id}/permissions` — owner grants/updates READ/EDIT.
- `GET /documents/{id}/permissions` — owner lists permissions.
- `DELETE /documents/{id}/permissions/{user_id}` — owner revokes permission.
- `DELETE /documents/{id}` — owner deletes file.
- `GET /admin/users`, `GET /admin/audit-logs`, `GET /admin/audit-logs/verify` — admin only.

## Security notes

This is a portfolio project, not a production security certification. The server checks permissions on every document request; revocation blocks future server downloads, but cannot erase a copy already downloaded by a recipient. The audit log uses a SHA-256 hash chain to reveal accidental/tampering changes when verified. A privileged attacker who can rewrite the database and recompute every hash may still rewrite the entire chain; strong tamper evidence requires independent signed checkpoints or external append-only logging. Denied download and metadata-update attempts are recorded. Audit rows for deleted documents remain, with their `document_id` cleared to satisfy foreign-key constraints.

Uploads are limited by filename extension and size; production should also validate file signatures/content, scan files for malware, use rate limiting, CSRF protections if cookie auth is introduced, TLS, backup/restore testing, and private durable object storage. The demo frontend keeps the short-lived bearer token in `sessionStorage`, which remains accessible to JavaScript; use a hardened same-site HttpOnly cookie/session design and a strong CSP for production.
